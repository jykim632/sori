# 기획자 피드백 - Sori 프로젝트 평가

> 작성일: 2025-01-10
> 평가 시점 완성도: 71%

## 종합 평가: 71점 / 100점

**MVP로서는 잘 만들어졌지만, 시장에서 살아남기엔 부족한 부분이 보입니다.**

---

## 잘한 점

### 1. 기술적 차별점이 명확함
- **3.2KB 위젯**은 진짜 경쟁력입니다. Hotjar(200KB+), Intercom(100KB+) 대비 압도적으로 가볍습니다
- Shadow DOM으로 스타일 격리한 것도 실무적 판단이 좋았습니다

### 2. 온보딩 플로우가 깔끔함
- 회원가입 → 이메일 인증 → 조직 생성 → 바로 대시보드
- 프로젝트 생성하고 코드 복사까지 2분이면 충분합니다

### 3. 코드 품질이 높음
- TypeScript + Zod로 타입 안전성 확보
- Rate Limiting, CORS, SSRF 방지 등 보안 기본기 탄탄

---

## 냉정하게 짚어야 할 문제점

### 1. "왜 Sori를 써야 하는가?"에 대한 답이 약함

현재 제품은 기능 나열만 있고, **핵심 가치 제안(Value Proposition)**이 불명확합니다.

| 경쟁사 | 그들의 포지션 |
|--------|--------------|
| Hotjar | "사용자 행동을 이해하라" (히트맵, 녹화) |
| Canny | "피드백으로 로드맵을 만들어라" (투표, 로드맵) |
| Intercom | "고객과 대화하라" (실시간 채팅) |
| **Sori** | "피드백을 수집하라" ← 이게 끝? |

**"가볍다"는 기술적 장점이지, 고객이 사는 이유가 아닙니다.** 고객은 "피드백을 수집해서 뭘 할 수 있느냐"를 묻습니다.

**제안:** 포지셔닝을 명확히 하세요.
- A안: "개발자를 위한 가장 빠른 피드백 위젯" (기술 블로그, 오픈소스 프로젝트 타겟)
- B안: "스타트업을 위한 올인원 VOC 수집" (작은 팀, 간단한 니즈)
- C안: "고객 목소리를 슬랙으로" (슬랙 중심 팀 타겟)

---

### 2. 수집만 있고, 액션이 없음

피드백을 수집하면 끝입니다. 그 다음이 없습니다.

현재 플로우:
```
고객이 피드백 제출 → 대시보드에 쌓임 → ...그 다음은?
```

**빠진 것들:**
- 피드백에 댓글 달기 (스키마만 있고 UI 없음)
- 고객에게 응답 보내기 (이메일 알림 미구현)
- 피드백 분석/통계 (대시보드 없음)
- 피드백 기반 로드맵/투표 (경쟁사 핵심 기능)

**이건 심각한 문제입니다.** 피드백 수집 도구의 핵심 가치는 "수집" 자체가 아니라 "수집 후 대응"입니다.

---

### 3. 요금제가 기능 차별화 없이 웹훅 개수로만 나뉨

```
FREE: 웹훅 1개
PRO: 웹훅 5개
TEAM: 웹훅 10개
ENTERPRISE: 웹훅 50개
```

**문제:**
- 웹훅 1개로도 슬랙 연동은 됩니다. PRO로 업그레이드할 이유가 약합니다
- 프로젝트 수, 피드백 수, 팀원 수 제한이 없어서 Free tier에서 계속 쓸 수 있습니다

**제안:** 플랜별 가치 계층화가 필요합니다
- Free: 월 피드백 100개, 프로젝트 1개
- Pro: 월 피드백 1,000개, 프로젝트 5개, 분석 대시보드
- Team: 무제한 피드백, 팀 협업, SLA

---

### 4. 타겟 고객이 누구인지 모르겠음

현재 기능 셋을 보면:
- 멀티테넌트 → 대기업/에이전시?
- 3.2KB 경량 → 성능 민감한 개발자?
- 한국어 기본 → 한국 시장?
- Slack/Discord 연동 → 스타트업?

**다 잡으려다 아무도 못 잡습니다.**

PMF(Product-Market Fit)를 찾으려면 타겟을 좁혀야 합니다. 지금은 "피드백 수집이 필요한 모든 사람"인데, 이건 타겟이 아닙니다.

---

### 5. 미완성 기능이 눈에 띄게 보임

- 댓글 기능: 스키마는 있는데 UI 없음
- 우선순위: enum만 있고 설정 UI 없음
- `/apps/cdn`: 폴더만 있고 구현 없음
- React 래퍼: 패키지만 있고 내용 없음

**80% 완성된 기능 5개보다, 100% 완성된 기능 3개가 낫습니다.** 미완성 기능은 지우거나 완성하세요.

## 우선순위 제안

### 지금 당장 (P0)
1. **댓글 기능 완성** - 피드백에 팀원이 코멘트 달 수 있어야 협업이 됨
2. **고객 응답 기능** - 피드백 작성자에게 이메일로 답변 보내기
3. **타겟 고객 1개 정하기** - 랜딩 페이지 메시지 재작성

### 다음 단계 (P1)
4. **분석 대시보드** - 피드백 추이, 타입별 비율, 해결율 등
5. **플랜별 기능 제한 추가** - 무료 유저의 유료 전환 경로 설계
6. **API 문서화** - 개발자가 타겟이라면 필수

### 버리거나 나중에 (P2+)
- apps/cdn (당장 필요 없음, main에서 서빙해도 됨)
- React 래퍼 (수요 확인 후 개발)
- 카카오 채널 연동 (니즈 불명확)

## 핵심 조언

1. **"무엇을 만들까"보다 "누구를 위해 만드는가"를 먼저 정하세요.** 지금은 기능을 쌓고 있지만 방향이 없습니다.

2. **수집 → 분석 → 액션의 루프를 완성하세요.** 수집만 있는 도구는 스프레드시트랑 다를 게 없습니다.

3. **런칭하고 고객 피드백을 받으세요.** 71% 완성도면 런칭 가능합니다. 실제 사용자 10명이 코드 100줄보다 가치 있습니다.
